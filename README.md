# 纯二维码文件传输工具（QR File Transfer）

一个「纯二维码」文件传输工具：把文件编码成多张二维码，在电脑屏幕上以**多码网格**循环显示；手机用 App 连续扫码，重组并保存文件。

传输通道**只有视觉二维码**——不联网、不用蓝牙、不插数据线，严格单向（电脑 → 手机）。

## 工作原理

1. 发送端把文件切成固定大小的数据块，每块生成一张二维码；另加一张「元数据」二维码，携带文件名、大小、总块数、整文件 SHA-256。
2. 所有二维码（元数据算第一张）按每屏 2 / 4 / 6 张排成网格，按「屏」**循环播放**。
3. 接收端持续扫码，每帧画面可同时解出多个码，按块号去重、乱序收集；漏掉的屏下一轮会被补上。
4. 收齐所有块后，用 SHA-256 校验整文件，通过则保存。

```
屏 0： [元数据, 块0, 块1, 块2]     ← 4 张模式（2×2）
屏 1： [块3,  块4,  块5,  块6]
屏 2： [块7,  块8,  块9,  块10]
...循环，直到接收端收齐
```


## 传输协议（要点）

- 每张二维码 = 一帧，二进制结构，公共头 10 字节大端：`magic("QRT1") + version(1) + type(1) + totalChunks(4)`
- 两种帧类型：`METADATA`（文件名 + 大小 + SHA-256）和 `DATA`（块号 + 数据）
- `totalChunks` 写进**每一帧**，接收端中途加入也能立刻知道总数
- 固定分块 + 循环轮播 + 全文件 SHA-256 校验，无需反向信道
- **多码网格不改协议**：每张码仍独立装一个块、自带块号，网格只改变显示与读取方式，两端可独立升级
- 完整格式见 `docs/superpowers/specs/2026-08-26-qr-file-transfer-design.md`，网格设计见 `docs/superpowers/specs/2026-08-31-multi-qr-grid-design.md`

## 功能特性

**发送端（桌面 GUI）**
- 选择文件，可选块大小（256 / 512 / 1024，默认 256）与帧率（2~15，默认 5）
- 全屏循环播放，每屏 **2 / 4 / 6 张**二维码：4 张固定 2×2、6 张固定 2×3（铺满宽屏）；2 张可选横向/纵向（适配手机竖屏拍摄）
- 传输中可**实时调整**帧率、二维码尺寸、张数、排列
- 紧凑排版（二维码占满格子，只留规范静区），窗口缩放自动重渲染
- 手动补漏：输入块序号单张全屏显示，或单独显示元数据（配合接收端「查看缺失」）
- 状态栏显示「当前: 屏 X：块 a~b / 共 Y 屏」

**接收端（手机 App）**
- CameraX 实时扫码 + 进度条，分析流 1080p（默认 640×480 在网格下不够用）
- **一帧解多码**：ZXing `GenericMultipleBarcodeReader` 逐码解码，一屏网格一次收多块
- 「查看缺失」：查看哪些块还没收到
- 收齐后 SHA-256 校验、自动保存，弹「打开 / 分享」对话框

## 运行

### 发送端（需要 JDK 17+ 和 Maven）

```bash
cd sender
mvn exec:java -Dexec.mainClass=com.qrtransfer.sender.Main
```

选文件 → 设置块大小/帧率 → 点「选择文件并开始传输」→ 全屏循环播放二维码网格。

推荐参数：**块大小 256 + 帧率 3~5 + 张数 4**。帧率低一点反而传得快——每屏停留久、手机命中率高，少走冤枉轮次。

### 接收端（需要 Android Studio + Android SDK API 34）

1. 用 Android Studio 打开 `receiver/` 目录
2. 连接真机，点 Run 安装运行
3. 授权相机，对准发送端屏幕即可

> 接收的文件保存在 app 私有目录 `Android/data/com.qrtransfer.receiver/files/Download/`；收完可在对话框里直接「打开 / 分享」。

## 已知限制

- 吞吐约 KB/s 量级，适合小文件（几十 KB ~ 几 MB）
- 一屏 6 张时受解码器约 5 码上限影响，每帧可能漏 1 个码，靠下一轮循环补齐（**4 张是稳定甜点**）
- 顺序轮播下，对焦/抖动的时间窗口会造成「成片缺失」，属正常现象，多转几轮自动补齐
- 排列方向需按手机横竖屏手动选择（单向信道，发送端感知不到手机方向）
- 未来扩展方向：喷泉码（Raptor codes）抗丢帧、乱序轮播打散缺失
